# 우리반 퀘스트 보드 — Design

> 출처: `prd/우리반_퀘스트보드.html` (단일 파일 프로토타입)
> 용도: 교실 TV·전자칠판에 띄워 두고 선생님과 학생이 함께 쓰는 3열 퀘스트(칸반) 보드. 퀘스트를 클리어하면 별을 모아 학급 목표를 달성한다.

---

## 1. 디자인 원칙

- **교실 거리에서 읽힌다** — 제목 22px 이상, 컬럼 제목 26px, 헤더 36px. 터치·클릭 대상은 최소 44×44px.
- **놀이 같은 톤** — 제목·숫자에는 둥근 손글씨풍 `Jua`, 본문에는 `Noto Sans KR`. 별·금색 강조로 보상감을 준다.
- **상태가 색과 모양으로 구분된다** — 대기(흰 카드+그림자), 도전 중(금색 테두리), 클리어(연노랑 가로형 카드+별).
- **되돌릴 수 있다** — 모든 이동에 "되돌리기"가 있고, 별은 이동에 따라 자동으로 더하고 뺀다. 되돌릴 수 없는 작업(초기화)만 확인창을 띄운다.

## 4. 컴포넌트

### 4.1 헤더
- 배경 `--primary`, 글자 흰색, 반경 20px, padding 22px 26px.
- **진행 바**: 높이 20px, 반경 10px, 트랙 `rgba(255,255,255,.22)`, 채움 `--accent`, `width` 전환 0.4s. `role="progressbar"`, `aria-valuenow` = 퍼센트(최대 100).
- **목표 상태 문구**: 미달성 "앞으로 별 N개" / 달성 "목표 달성! 축하해요".
- **Ghost 버튼**: 높이 44px, 투명 배경, `2px solid rgba(255,255,255,.5)`, hover `rgba(255,255,255,.12)`.

### 4.2 컬럼
- 헤더: Jua 26px 제목 + 카운트 배지(`--primary` 배경, 흰 글자, 반경 12px, padding 2px 10px).
- 최소 높이 200px, padding 6px.
- **드래그 오버**: 배경 `rgba(30,42,90,.08)` + `outline: 3px dashed var(--shadow)`.
- **새 퀘스트 버튼**(첫 컬럼만): 높이 44px, `2px dashed var(--muted)`, 투명 배경, hover `rgba(255,255,255,.5)`.
- **빈 상태**(14px, `--muted`, 가운데):
  - 퀘스트 게시판: "새 퀘스트를 만들어 보세요"
  - 도전 중: "카드를 여기로 끌어오거나 "도전하기"를 눌러요"
  - 클리어!: "아직 클리어한 퀘스트가 없어요"

### 4.3 퀘스트 카드

공통: 흰 배경, 반경 16px, 하단 그림자, `cursor: grab`, `draggable`. 드래그 중 `opacity: .5`.

| 상태 | 모양 | 구성 | 액션 |
|---|---|---|---|
| **대기** (`todo`) | 흰 카드 + 하단 그림자 | 배지·"별 +N" / 제목 / (아바타) / 메타 | [✏ 고치기] [도전하기] |
| **도전 중** (`doing`) | `3px solid --accent` 테두리, 그림자 없음 | 위와 같음 | [✏ 고치기] [↩ 되돌리기] [클리어!(금색)] |
| **클리어** (`done`) | `--done` 배경, 가로 배치, 그림자 없음 | 40px 별 아이콘 / 제목 + "참여자 또는 대상 · 별 +N 받음" | [↩ 되돌리기] |

- **메타 줄**: "대상(우리반 모두 / 개인 / 모둠 이름) · 메모".
- **아바타**: 높이 34px, 최소 폭 34px, 이름이 길면 가로로 늘어나는 알약형. 최대 6명.
- **버튼**
  - 기본 `.btn`: `--primary` 배경, 흰 글자, `flex: 1`, hover `brightness(1.25)`.
  - 금색 `.btn.gold`: `--accent` 배경, `--ink` 글자.
  - 아이콘 `.icon-btn`: 44×44, `#EEF1FA` 배경, `--muted` 아이콘, hover `#DFE5F5` / `--ink`. 반드시 `aria-label`과 `title`을 단다.
- **아이콘**: 20px 선형 SVG, stroke 2.2, round cap/join, `currentColor`.
  - 고치기: 연필 `M4 20h4L19 9l-4-4L4 16z`
  - 되돌리기: 꺾인 화살표 `M9 14L4 9l5-5` + `M4 9h10a6 6 0 0 1 0 12h-3`
  - 별(클리어): 40px, 채움 `#FFD166`, 외곽선 `#8A5A00` 1.5

### 4.4 모둠 별 순위
- 흰 패널, 반경 16px, padding 16px 18px, gap 10px.
- 제목 "모둠 별 순위"(Jua 20px). 각 행 "N위 · 모둠 이름" ↔ **점수**, 점수 내림차순.

### 4.5 대화상자 (`<dialog>`)
- 폭 `min(460px, 92vw)`, 반경 20px, 내부 padding 24px, gap 14px, backdrop `rgba(20,27,54,.45)`.
- **필드**: 라벨 14px 700 / 입력·선택 높이 44px, `2px solid --shadow`, 반경 12px, focus 시 테두리 `--primary`(기본 outline 제거). 2열이 필요하면 `grid2`(gap 10px).
- **액션 줄**: 오른쪽 정렬. 위험 버튼은 왼쪽 끝, 가운데 spacer, 오른쪽에 [취소(light)] [저장(primary)].

| 대화상자 | 제목 | 필드 |
|---|---|---|
| 퀘스트 | "새 퀘스트" / "퀘스트 고치기" | 퀘스트 이름(필수, 40자) · 난이도 · 누가 하나요?(우리반 모두/개인/모둠1~4) · 참여하는 친구(선택, 쉼표 구분, 60자) · 메모(선택, 40자). 고치기일 때만 [삭제] |
| 보드 설정 | "보드 설정" | 반 이름(30자) · 학급 목표 문구(40자) · 목표 별 수(1–9999) · 지금 별 수(0–99999) · 1~4모둠 이름(각 12자). [처음부터 다시] |
| 초기화 확인 | "정말 처음부터 할까요?" | 안내문 "모든 퀘스트와 별이 지워지고 예시 보드로 돌아가요. 되돌릴 수 없어요." [취소] [지우기(danger)] |

플레이스홀더 예시: "예: 영어 단어 10개 외우기", "예: 서연, 민준, 지호", "예: 금요일까지 · 2단계 중 1단계".

### 4.6 토스트
- 화면 하단 가운데(bottom 32px), `--primary` 배경, 흰 Jua 20px, 반경 14px, padding 14px 22px.
- 등장: 아래 20px에서 올라오며 페이드인(0.3s), 2.2초 뒤 사라짐. `role="status" aria-live="polite"`.
- 문구: "클리어! 별 +N" / 목표를 이번에 넘겼다면 "목표 달성! {학급 목표 문구}".

## 5. 인터랙션·규칙

### 5.1 이동
- 버튼: 대기 →[도전하기]→ 도전 중 →[클리어!]→ 클리어. [되돌리기]는 한 칸 뒤로(클리어 → 도전 중 → 대기).
- 드래그 앤 드롭: 카드를 아무 컬럼에나 놓을 수 있다(건너뛰기 허용).
- 옮긴 카드는 해당 컬럼 **맨 위**로 간다. 새 퀘스트도 대기 컬럼 맨 위에 추가된다.

### 5.2 별 계산
- 클리어 컬럼에 **들어갈 때** 난이도 보상만큼 학급 별 +, 대상이 모둠이면 그 모둠 별도 +.
- 클리어 컬럼에서 **나갈 때** 또는 클리어 카드를 **삭제할 때** 같은 만큼 뺀다(0 미만으로 내려가지 않음).
- 클리어 카드의 난이도·대상을 고치면 이전 값만큼 빼고 새 값만큼 더한다.
- "개인", "우리반 모두" 퀘스트는 학급 별에만 반영된다.
- 설정의 "지금 별 수"는 학급 별을 그 값으로 직접 맞춘다(모둠 별은 그대로).

### 5.3 기타
- **전체 화면**: 교실 TV용. 버튼 문구가 "전체 화면" ↔ "전체 화면 끄기"로 바뀐다.
- **저장**: 브라우저 `localStorage`(`class-quest-board-v1`)에 바로 저장. 데이터가 없으면 예시 보드로 시작.
- **초기화**: 설정 → [처음부터 다시] → 확인 대화상자 → 예시 보드로 되돌림.
- **빈 입력 처리**: 설정에서 비워 둔 칸은 기존 값을 유지한다.

## 6. 데이터 모델 (프로토타입 기준)

```ts
type Column = 'todo' | 'doing' | 'done';
type Level = 'easy' | 'normal' | 'hard';      // 별 2 / 5 / 10
type Target = 'all' | 'solo' | '1' | '2' | '3' | '4'; // 모둠은 1부터 시작하는 번호

interface Quest {
  id: string;
  title: string;      // ≤40
  level: Level;
  group: Target;
  people: string[];   // ≤6명
  note: string;       // ≤40
  col: Column;
}

interface BoardState {
  className: string;  // ≤30
  goal: string;       // ≤40
  target: number;     // 1–9999
  stars: number;      // ≥0
  groups: { name: string; stars: number }[]; // 4개 고정
  quests: Quest[];    // 배열 순서가 곧 화면 순서
}
```

예시 데이터: "4학년 2반 퀘스트 보드", 목표 "별 200개 모으면 영화 보는 날!", 146/200, 모둠 해바라기 38 · 무지개 31 · 별빛 42 · 초록숲 35.

## 7. 접근성 체크

- 모든 상호작용 대상 ≥ 44px.
- 아이콘만 있는 버튼에 `aria-label` + `title`.
- 진행 바 `role="progressbar"` + `aria-label="학급 목표 진행"` + `aria-valuenow`.
- 토스트 `aria-live="polite"`.
- 대화상자는 네이티브 `<dialog>`의 `showModal()` 사용(포커스 가두기·Esc 닫기). 열리면 첫 입력에 포커스.
- 사용자 입력은 출력 전에 HTML 이스케이프.
- ⚠️ 프로토타입 한계: 드래그 앤 드롭은 키보드 대안이 버튼뿐이며(충분히 대체됨), 진행 바에 `aria-valuemin/max`가 없다 — 구현 시 추가 권장.
