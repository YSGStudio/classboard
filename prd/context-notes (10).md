# Context Notes: 수업용 계층형 칸반 보드

`implement`가 같은 탐색을 반복하지 않도록 남기는 기반 노트다.

## 코드베이스 상태

- 아직 저장소가 없다. 탐색할 기존 코드, 설정, `CLAUDE.md`/`AGENTS.md`/`README.md`가 없다.
- 따라서 PRD의 스택·DB 결정은 파일이 아니라 사용자와 합의한 문서에 근거한다.
  - 개발 계획서(Claude Docs, "개인용 칸반 보드 도구 개발 계획서")
  - PRD 문서(Claude Docs, "PRD: 수업용 계층형 칸반 보드")

## 확정된 관례·결정

- 스택: Next.js App Router + TypeScript + Tailwind CSS + dnd-kit + pdf.js
- DB·인증·파일·실시간: Supabase(Postgres, Auth, Storage, Realtime), `@supabase/ssr`로 서버·클라이언트 세션 처리
- 데이터 접근: 초기 조회는 Server Component, 변경은 Server Action, 칸반 상호작용은 Client Component
- 권한은 모두 DB(RLS)·Storage 정책에서 강제하고, 화면은 그 결과만 보여 준다

## 사용자가 명시한 요구(바꾸지 말 것)

- 보기 형식은 칸반만 쓴다(Card·Canvas 없음).
- 보드는 깊이 제한 없이 계층으로 만든다.
- 보드 하나를 칸반으로 그대로 쓰면서 그 아래에 학생별 개인 하위 보드를 배당한다.
- 보드별 읽기·수정 권한은 교사가 학생을 골라 준다.
- 참여 코드 없이, 교사가 등록한 학생은 그 교사의 모든 프로젝트에 들어간다.
- 교사는 구글 로그인, 학생은 교사가 발급한 아이디 + **4자리** 비밀번호를 쓴다.
- 평가는 카드가 아니라 학생의 보드 전체를 단위로 하며, 교사가 기준을 등록하고 보드마다 붙인다.
- 링크·이미지·PDF는 모두 미리보기를 제공한다.

## 구현 시 주의할 제약

- Supabase Auth 비밀번호는 최소 6자다. 4자리를 그대로 쓰지 말고 서버에서 `HMAC-SHA256(STUDENT_PASSWORD_PEPPER, login_id:비밀번호)`로 바꿔 쓴다.
- 4자리 비밀번호는 추측에 약하다. 아이디별 5회 실패 시 5분 잠금을 서버(`login_attempts`)에서 반드시 구현한다. 교실은 공용 IP라 IP 기준 제한에 기대지 않는다.
- Realtime `postgres_changes`로 카드 행을 직접 구독하면 가리기 "익명" 모드에서 작성자가 이벤트에 실린다. 반드시 `board_events` 신호 → `get_board_view` 재조회 방식을 쓴다.
- 보드 트리는 깊이 제한이 없다. 순환 참조를 DB 트리거로 막고, 트리는 프로젝트 단위 한 번 조회로 만든다.
- 링크 미리보기는 SSRF 위험이 있다. 공인 IP만 허용하고, 리디렉션마다 다시 검사하며, 시간 5초·응답 1MB로 제한한다.
- Storage 버킷은 비공개로 두고 서명된 URL만 쓴다.
- service role 키는 학생 계정 발급·재발급과 개인 하위 보드 배당 Server Action에서만 쓰고, 클라이언트 번들에 넣지 않는다.

## 미확정(구현 전 사용자 확인 권장)

- 수정 권한이 있는 학생이 다른 학생 카드를 옮길 수 있는가 → 현재: 못 옮김
- 상위 보드 권한 변경을 하위 보드가 계속 따라갈지 → 현재: 생성 때만 복사
